# วิธีทำงานร่วมกันสองคนผ่าน Codex และ GitHub

## เตรียมแต่ละคน

1. รับคำเชิญ repository และเปิด Go-Kart-Sim บน GitHub ให้ได้
2. เชื่อม GitHub กับ Codex ด้วยบัญชีของตัวเอง แล้วเลือก repository นี้
3. เริ่มจากอ่าน README และ Context ไม่ต้องคัดลอกประวัติแชททั้งหมด

## วงจรส่งงาน

1. ระบุงานและผู้รับผิดชอบใน Issue หรือ docs/tasks.md ก่อนแก้ไฟล์เดียวกัน
2. ตรวจไฟล์ค้างใน checkout และดึง main ล่าสุดโดยไม่ทับงาน ใช้ branch ใหม่ เช่น mechanical/seat-layout หรือ electrical/gm5-test
3. บันทึกข้อมูล แหล่งอ้างอิง สมมติฐาน และผลตรวจ อย่าล็อกข้อเสนอเป็นข้อกำหนดเอง
4. ตรวจ diff แล้ว commit และ push เฉพาะ branch งาน
5. เปิด Pull Request ให้เพื่อนตรวจข้อเปลี่ยนแปลงและแสดงความคิดเห็น
6. เมื่อได้รับอนุมัติตามกติกาทีม ให้ผู้รับผิดชอบ merge แล้วแต่ละคนดึง main ล่าสุดก่อนงานถัดไป

แนะนำตั้งกฎ main ให้ผ่าน PR และมีอีกคนอนุมัติหนึ่งคน ตามความสามารถแผน GitHub กฎนี้ต้องตั้งใน GitHub จริง เอกสารนี้ไม่ได้เปิดใช้ branch protection ให้อัตโนมัติ

## คำสั่งเริ่มงานกับแชท

> ตรวจ git status และ remote ล่าสุด อ่าน AGENTS.md, Gokart_IDEA/PROJECT_CONTEXT.md, docs/decisions.md และ docs/tasks.md แล้วทำงาน [รหัสงาน] บน branch ใหม่ รักษางานค้างเดิม เมื่อเสร็จให้ตรวจ commit push และเปิด Pull Request พร้อมผลตรวจ

## งาน CAD และไฟล์ใหญ่

กำหนดเจ้าของไฟล์ CAD แต่ละชุดก่อนแก้ เพราะรวมการแก้พร้อมกันยาก ไฟล์วิดีโอและภาพเดิมเก็บตามตำแหน่งเดิม ก่อนเพิ่มไฟล์ใหญ่จำนวนมากให้ตัดสินใจ Git LFS หรือพื้นที่แชร์ ไม่ย้ายประวัติเป็น LFS โดยไม่มีแผนร่วมกัน

## เมื่อเปิด PR จากแชทไม่ได้

Git fetch/push กับ GitHub API ใช้สิทธิ์และเส้นทางต่างกัน จึงอาจ push ได้แต่สร้าง PR ไม่ได้ ให้ใช้ลิงก์ compare ที่ GitHub ส่งกลับเพื่อสร้าง PR ในเว็บ อย่าส่ง token ในแชท หากต้องเปิด API ให้กำหนด api.github.com ใน environment settings และตรวจสิทธิ์หลังบันทึกใหม่

GitHub เก็บไฟล์และสถานะงาน ส่วนการตั้งค่า environment และประวัติแชทของแต่ละบัญชีไม่ได้ซิงก์อัตโนมัติ
