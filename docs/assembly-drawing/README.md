## วิธีอ่านและข้อจำกัด

- S คือ datum บนผิวเบาะบริเวณรองก้นชิดพนัก ขณะรางอยู่กลางช่วง ไม่ใช่ anatomical H-point เมื่อเลื่อนเบาะต้องตรวจระยะ S–อุปกรณ์ใหม่
- พิกัดมาจาก [layout-v04.json](../dimension-study/layout-v04.json) และ [ผลศึกษาท่านั่ง/วัสดุ](../seating-materials-assembly-th.md) คงข้อมูลเดิม ไม่ได้วัดอุปกรณ์หรือเพิ่มมิติผลิตใหม่
- เส้นสีแดง = ระยะตัวอย่าง/อ้างอิงที่มีตัวเลข; สีน้ำเงิน = datum/ช่วงปรับ; สีเทา = รูปทรงจัดวางประกอบ เส้นทางท่อ/ค้ำ/เบาะ/ตำแหน่งจอ/ระดับยางเป็นสัญลักษณ์ ไม่ใช่รูปทรงผ่านตรวจ
- กรอบ 1,800 × 1,300 ไม่รวมจอ/ขาจอที่ยื่น ระยะกวาด Motion และทางเดิน และห้ามใช้แทนระยะแนวศูนย์กลางท่อหรือขนาดโครงเชื่อมเปล่า
- จอสามตัวในมุมหน้าเป็นภาพฉายกรอบ 615 × 365 ที่มุมข้างตัวอย่าง 50° ความกว้างฉายประมาณ 1,406 ไม่รวมช่อง/แขนยึด กรอบเผื่อ layout เดิม 1,500–1,700 ยังไม่ใช่ขนาดผลิต
- ระยะขาปรับเป็น TOTAL travel เท่านั้น ไม่ได้ระบุความยาว slot ระยะรู จุดล็อก หรือจุดหยุดจริง
- ขนาดยางในภาพและค่า Z ของแป้น/ล้อ/จอเป็นเพียงตัวอย่างจัดวาง ไม่มีเส้นพื้นห้องหรือพิกัดความสูงติดตั้ง GM5 ที่ยืนยันแล้ว
- อ่านจากตัวเลขเท่านั้น (NTS) ไม่วัดจากกระดาษ/รูปย่อ ไม่ใช้แทน cut list, bend drawing, drill template หรือแบบ CAD ที่ผ่านผู้ตรวจ

**ยังไม่มีมิติพอให้สั่งตัดท่อทั้งโครง:** ต้องวัดรู/XYZ ของ GM5 เบาะ/ราง อุปกรณ์ขับ จอ/VESA แล้วทำ CAD ตรวจโหลด แนวท่อ ระยะคาน ความยาวตัด รัศมีดัด รอยเชื่อม ค่าคลาดเคลื่อนและจิ๊กก่อนปล่อยผลิต รายการครบอยู่แผ่น 06 และ [กระบวนการผลิต](../manufacturing-workflow-th.md)

## สร้างซ้ำและผลตรวจ

รันจาก root โดยมี Python `reportlab`, `PyMuPDF` และฟอนต์ Noto Sans / Noto Sans Thai:

```sh
python docs/assembly-drawing/render-drawing.py
```

ใช้พิกัดชุดเดียวสร้าง PDF เวกเตอร์ จากนั้นส่งออก SVG และ PNG แต่ละแผ่นจาก PDF เดียวกัน ไม่มีการแก้ภาพ AI หรือเอาภาพเดิมมาวัดระยะ SVG ใช้เส้นเวกเตอร์/ตัวอักษรแปลงเป็น path ส่วน PDF เก็บข้อความและฝังฟอนต์

ตรวจผลต่างพิกัด 400/900/500, แนวดิ่ง 120/300/420, ฐานล้อ 1045, ความกว้าง 1300 และระยะแป้น 360 เทียบต้นทาง ตรวจ PDF 6 หน้า A3 แนวนอน ตัวเลข/ตัวอักษรไม่หลุดขอบ และภาพรวมทั้งหกแผ่นแล้ว ยังไม่ตรวจ CAD/โหลด รูยึด หรือทดสอบชิ้นงานจริง
